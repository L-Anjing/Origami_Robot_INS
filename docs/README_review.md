# README 表达审校

本次审校覆盖根目录 `README.md`、`test/README.md` 与 `test/ros2/README.md`。叙事围绕三项能力展开：多 IMU 形态与位移协同呈现、ESKF 与静止事件融合、真实时间戳驱动的实机轨迹和朝向验证。

## 防御性表达及改法

| 原句 | 表达问题 | 已采用的改法 |
| --- | --- | --- |
| “本包只验证 IMU 轨迹与朝向，没有点云、地图或回环模块。” | 以“只”“没有”开场，主动引入任务范围外的比较。 | “围绕 INS 轨迹与朝向提供完整的回放和观察入口。” |
| “TXT 的设备四元数仅供查看。” | “仅供”强调用途受限，弱化数据角色。 | “设备四元数作为录制信息保留，INS 姿态由加速度计和陀螺仪独立估计。” |
| “估计对象是 IMU 原点，未配置机体外参。” | 以缺少配置解释坐标定义。 | “位姿定义在 IMU 原点，机体系与传感器系重合。” |
| “六轴 IMU 没有绝对航向参考。” | 以缺失信息引出航向，读者先看到局限。 | “航向由陀螺仪相对初始方向传播，因此采用相对航向口径，并随积分时间累积误差。” |
| “这里显示的是相对位姿估计，不能仅凭轨迹形状判定位置精度。” | 用否定句结束观察说明，替读者作负面总结。 | “实机实验以相对轨迹、姿态变化和静止段速度为观察量；绝对位置精度以同步位置参考为评价基准。” |
| “位移属于惯性估计量；位置精度评价需配套位置参考。” | 将评价设计写成能力不足后的补充说明。 | “实验以 Raw INS 和 ESKF 的轨迹形态、静止段速度及零速更新响应，分析静止约束对惯性状态的作用。……位置精度实验以同步位置参考为评价基准。” |
| “静止检测基于 IMU 特征，需结合录制动作确认静止区间。” | “需结合”形成追加条件式收尾。 | “录制动作作为静止区间的核对依据。” |
| “噪声与阈值为可调实验参数，实际硬件部署前需标定。” | 以准备工作收尾，削弱集中配置带来的复用价值。 | “在 config.json 中集中配置……支持将硬件标定结果直接用于对应实验。” |

## 叙事重心调整

以下原句属于工程介绍或技术约定，本身并非防御性表达；修改目的是让优势先被看见。

| 原有写法 | 调整后的职责 |
| --- | --- |
| “面向……的 Python–MATLAB 验证工程” | 开篇从节段形变与整体位移的联合表达问题切入，再引出多 IMU 姿态、运动学与 ESKF 的组合。 |
| “形态与导航独立计算……” | 主动说明“由参考 IMU 位姿统一呈现”，将模块化设计与使用价值连接起来。 |
| “XML 几何读取无需安装 MuJoCo Python 包。” | 改为“几何模块直接读取 MuJoCo XML 中的板体尺寸与连接关系”，明确实际能力。 |
| “滤波仍处理每个 IMU 样本。” | 先说明滤波逐帧处理，再说明轨迹取样和发布频率，强调计算与显示频率的独立配置。 |
| 按模块列功能，实验职责分散 | 增加实验设计表，逐项明确形态协同、零速约束、驱动相位及跨采样率处理各自验证什么。 |

初始静止条件、局部坐标系、相对航向定义、协方差占位值和位置参考口径均保留为明确的技术定义。README 的记忆点统一为：形态与位移协同呈现，静止事件约束惯性状态，实测数据统一接入。
